# Data contract

Dashboard รับข้อมูลราคาปิดแบบ CSV ที่ตรวจรูปแบบได้ แล้วคำนวณจากวันที่ที่หุ้นและ benchmark มีข้อมูลร่วมกัน เอกสารนี้กำหนดความหมายของข้อมูลและตัวเลข เพื่อให้คนและ Agent ใช้คำเดียวกัน

## รูปแบบ CSV

ไฟล์ UTF-8 ขนาดไม่เกิน 1 MiB (1,048,576 bytes) มีหัวตารางตามลำดับนี้:

```csv
date,symbol,close,volume
2026-10-01,MY_STOCK,10,1000
2026-10-01,MY_BENCHMARK,100,
2026-10-02,MY_STOCK,11,1200
2026-10-02,MY_BENCHMARK,105,
```

| คอลัมน์ | กติกา | ความหมาย |
|---|---|---|
| `date` | บังคับ; วันที่จริงรูปแบบ `YYYY-MM-DD` | วันที่ของราคานั้น ใช้ ค.ศ. |
| `symbol` | บังคับ; ต้องตรงกับชื่อใน config | รหัสหุ้นหรือ benchmark |
| `close` | บังคับ; ตัวเลข finite มากกว่า 0 | ราคาปิด หรือระดับดัชนี |
| `volume` | ไม่บังคับ | ปริมาณซื้อขายเมื่อมี โดยไม่ใช้แทนราคา |

ไม่รับวันที่อย่าง `01/10/26`, วันที่ไม่มีจริง, ราคาว่าง, ศูนย์, ค่าติดลบ, `NaN`, `Infinity` หรือ `(date, symbol)` ที่ซ้ำกัน อย่าใส่เครื่องหมายสกุลเงินหรือข้อความหน่วยไว้ใน `close`

ตัวอย่างนี้แสดงโครงสร้างเท่านั้น สองวันอาจไม่พอสำหรับ lookback ที่ตั้งไว้ ให้ใช้ชุดข้อมูลที่มีอย่างน้อย `lookback + 1` จุดที่จัดวันที่ตรงกัน

## จากไฟล์ Efin สู่รูปแบบนี้

1. เก็บไฟล์ต้นฉบับโดยไม่แก้ แล้วตรวจชื่อคอลัมน์และหน่วยจากไฟล์จริง
2. Map วันที่ รหัส และราคาปิดมาเป็น `date`, `symbol`, `close`
3. แปลงวันที่เป็น ISO ค.ศ. อย่างชัดเจน ไม่เดาวัน/เดือนหรือปี พ.ศ.
4. ตรวจว่าราคาเป็น adjusted หรือ unadjusted และใช้อย่างสม่ำเสมอ
5. จัดข้อมูล benchmark ให้มีวันที่ที่ต้องใช้จริง ระบุแหล่งและวันที่ดาวน์โหลดไว้ในบันทึกของคุณ

Starter ไม่มี mapping มาตรฐานที่รับรองว่าใช้ได้กับทุก export ของ Efin และยังไม่มี API adapter ผู้เรียนต้องตรวจสิทธิ์และรูปแบบข้อมูลที่ใช้จริงก่อนเชื่อมต่อ

## วันที่ร่วมกันและช่วงคำนวณ

จับคู่ราคาของหุ้นกับ benchmark ด้วยวันที่เดียวกัน เรียงวันที่เพื่อคำนวณ ไม่เติมราคาแทนวันที่ขาดและไม่ forward-fill วันปลายทางต้องตรงกับวันที่ล่าสุดของ benchmark หุ้นที่ไม่มีราคาในวันนั้นต้องแสดงสถานะข้อมูลขาด ไม่ใช้วันเก่าของหุ้นแทนโดยเงียบๆ

`lookbackPeriods` เริ่มต้น 21 ช่วง นับจำนวนช่วงระหว่างจุดข้อมูลที่จัดตรงกัน เช่น lookback 5 ต้องมี 6 จุด ไม่เท่ากับ 5 วันปฏิทินเสมอ วันหยุดหรือข้อมูลขาดทำให้ช่วงปฏิทินยาวขึ้นได้

ถ้าข้อมูลไม่พอ ต้องรายงานว่าคำนวณไม่ได้หรือข้อมูลขาด อย่าแสดงศูนย์แทนผลที่ไม่ทราบ และอย่าเปลี่ยนไปใช้ข้อมูลจำลองโดยไม่บอกผู้ใช้

## สูตรที่ใช้

กำหนด `P` เป็นราคาหุ้น, `B` เป็นระดับ benchmark, `t` เป็นจุดล่าสุดที่ใช้คำนวณ และ `n` เป็น lookback ที่เลือก:

```text
Stock return (%)     = (P[t] / P[t-n] - 1) × 100
Benchmark return (%) = (B[t] / B[t-n] - 1) × 100
Excess return (pp)   = Stock return - Benchmark return
```

สำหรับกราฟเปรียบเทียบผลการเปลี่ยนแปลง ให้ `0` เป็นจุดเริ่มต้นที่แสดงบนกราฟ ทั้งสองเส้นเริ่มที่ 100:

```text
Stock index[t]     = 100 × P[t] / P[0]
Benchmark index[t] = 100 × B[t] / B[0]
```

เส้นที่อยู่สูงกว่ามีผลตอบแทนสะสมนับจากจุดเริ่มต้นเดียวกันสูงกว่า ค่าหุ้นสูงกว่า 100 หมายถึงราคาเพิ่มจากจุดเริ่มต้น แต่ต้องดูเส้น benchmark ด้วยจึงจะบอกได้ว่า outperform หรือไม่

Excess return เป็นผลต่าง **percentage points** ส่วนเส้นกราฟเป็นราคาที่ rebase เป็น 100 สูตรนี้ไม่ได้อ้างว่าเป็น proprietary RRG หรือ JdK RS-Ratio/RS-Momentum การเพิ่มกราฟอัตราส่วนราคาหุ้นต่อ benchmark เป็นแบบฝึกหัดต่อยอดได้ แต่ยังไม่ใช่กราฟที่ starter แสดง

## ตรวจด้วยตัวอย่างเล็ก

หุ้นจาก 100 เป็น 110 และ benchmark จาก 200 เป็น 210:

- ผลตอบแทนหุ้น = 10%
- ผลตอบแทน benchmark = 5%
- Excess return = 5 percentage points
- เส้นหุ้นปลายช่วง = 110 และเส้น benchmark ปลายช่วง = 105

ถ้าหน้าจอปัดเศษ ให้เทียบค่าก่อนปัดในการทดสอบ และตรวจว่าตารางกับกราฟใช้วันเริ่มต้นเดียวกันก่อนเทียบความต่าง

## ความใหม่และการเก็บข้อมูล

`staleAfterDays` เป็นเกณฑ์เตือนอายุข้อมูล ไม่ใช่ตารางวันทำการ SET ที่ครบถ้วน วันหยุดต้องพิจารณาร่วมกับแหล่งข้อมูล

แยก **วันที่ของราคา** ออกจาก **เวลาที่นำเข้า** การนำเข้าไฟล์เก่าวันนี้ไม่ได้ทำให้ราคากลายเป็นราคาวันนี้

CLI บันทึกชุดข้อมูลที่ตรวจแล้วใน `data/private/current.json` ซึ่งถูก Git ignore การ import/refresh ต้องสำเร็จเมื่อข้อมูลผ่านการตรวจเท่านั้น หากรับไฟล์ไม่ได้ ให้เก็บข้อมูลชุดก่อนหน้าและแจ้งเหตุผล

การเลือก CSV ในเบราว์เซอร์ใช้ดูตัวอย่าง ส่วน `npm run import` และ `npm run refresh` ใช้บันทึกข้อมูลหลักในเครื่อง ไม่มีคำสั่งใดใน starter ส่งคำสั่งซื้อขาย
