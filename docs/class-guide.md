# คู่มือคลาส: คุยจนได้ Dashboard การลงทุนที่ถูกใจ

เป้าหมายคือให้คุณได้ Dashboard ที่ตอบคำถามการลงทุนของตัวเอง พร้อมรู้ว่าตัวเลขมาจากไหนและตรวจอย่างไร เริ่มจากการคุยกับ Agent แล้วเลือกหน้าตา สร้าง ทดลอง และปรับจากงานที่เห็นจริง

## 1. เปิดโปรเจกต์แล้วเริ่มคุย

สร้างสำเนาด้วย **Use this template** หรือดาวน์โหลด ZIP จาก repo แล้วเปิดโฟลเดอร์ในแอป Agent ที่อ่านและแก้ไฟล์กับรันโค้ดได้ ไม่ต้องเตรียม framework หรือรูปแบบข้อมูลล่วงหน้า

วางข้อความนี้:

```text
อ่าน START.md และ AGENTS.md แล้วใช้สกิล grill-with-docs จาก .agents/skills/grill-with-docs/SKILL.md ช่วยฉันออกแบบ Dashboard การลงทุน เริ่มจากถามว่าฉันอยากใช้หน้า Dashboard ช่วยตัดสินใจเรื่องอะไร คุยทีละประเด็นและจดข้อสรุปใน BRIEF.md
```

ตอบจากสิ่งที่คุณทำอยู่จริง เช่น “ฉันดูพอร์ตทุกวัน แต่ยังไม่เห็นว่ากระจุกในหุ้นกลุ่มไหน” หากยังคิดไม่ออก ให้ขอตัวอย่างโจทย์ 2–3 แบบแล้วเลือกสิ่งที่ใกล้ตัว

หากอยากให้ช่วยเลือกสกิลก่อน พิมพ์ **“ใช้สกิล ask-matt ช่วยเลือกวิธีเริ่มทำ Dashboard จากความต้องการของฉัน”** ได้เช่นกัน

**สิ่งที่ควรได้:** [BRIEF.md](../BRIEF.md) ที่สรุปผู้ใช้ คำถามหลัก สิ่งที่อยากเห็น ข้อมูลที่มีหรือยังขาด และเกณฑ์ว่าหน้านี้ช่วยคุณได้จริงอย่างไร

## 2. ขอเห็นแบบ แล้วเลือกสิ่งที่ชอบ

ใช้ภาษาธรรมดาได้ ไม่จำเป็นต้องรู้ศัพท์ออกแบบ:

```text
จากโจทย์ที่คุยกัน เสนอหน้าตา Dashboard 2 แบบให้เห็นภาพ
แต่ละแบบบอกว่าช่วยตอบคำถามหลักอย่างไร
ใช้ข้อมูลตัวอย่างที่ระบุชัดว่าเป็นข้อมูลจำลอง
ฉันอยากเลือกตำแหน่งกราฟ ตาราง และโทนสีก่อนสร้างรุ่นแรก
```

ให้ความเห็นเฉพาะจุด เช่น:

- “ใช้โครงของแบบแรก แต่ขอตารางจากแบบที่สอง”
- “ฉันดูบนมือถือเป็นหลัก ลดรายละเอียดหน้าหลักแล้วให้กดดูต่อได้”
- “อยากเห็นสัดส่วนพอร์ตก่อน แล้วค่อยดูผลตอบแทน”
- “ตัวเลขที่ไม่รู้ที่มาให้บอกว่ายังไม่มีข้อมูล ไม่ต้องใส่ค่าทดแทน”

**สิ่งที่ควรได้:** แบบที่เลือกและข้อสรุปใน brief พร้อมรายการสิ่งจำเป็นสำหรับรุ่นแรก ยังไม่ต้องทำทุกไอเดียพร้อมกัน

## 3. เปลี่ยนข้อสรุปเป็นงานที่สร้างได้

เมื่อภาพและขอบเขตชัดแล้ว ให้คุณเรียกสกิลสรุปสเปก:

```text
ใช้สกิล to-spec สรุปบทสนทนา BRIEF.md และแบบที่ฉันเลือกเป็นสเปก
ใช้รูปแบบการเก็บงานที่กำหนดใน AGENTS.md
ระบุหน้าจอ ฟังก์ชัน แหล่งข้อมูล วิธีตรวจตัวเลข และสิ่งที่ยังไม่ทำในรุ่นแรก
```

อ่านสรุปแล้วแก้สิ่งที่ไม่ตรงก่อนเริ่มสร้าง เช่น ข้อมูลที่ใช้จริงเป็นรายเดือน ไม่ใช่รายวัน หรือกำไรที่ต้องการดูรวมเงินปันผลด้วย

งานรุ่นเล็กเริ่มจากสเปกแล้วสร้างได้เลย เมื่อมีหลายส่วนที่ต้องทำตามลำดับ ค่อยเรียก `to-tickets` เพื่อแบ่งงาน และเลือก `implement-spec` หากต้องการทำทั้งชุด `wayfinder` เหมาะกับงานที่ใหญ่จนต้องวางแผนข้ามหลายรอบ ไม่จำเป็นสำหรับทุก Dashboard

**สิ่งที่ควรได้:** สเปกที่บอกได้ว่าจะสร้างอะไร และผู้เรียนจะตรวจว่าสำเร็จได้อย่างไร

## 4. สร้างรุ่นแรก แล้วเปิดลองใช้

```text
ใช้สกิล implement สร้าง Dashboard ตามสเปกนี้
เลือกเครื่องมือให้เหมาะกับงานและช่วยเตรียมเฉพาะสิ่งที่ต้องใช้
ทำรุ่นแรกที่เปิดลองได้ ตรวจฟังก์ชันและตัวเลขที่สำคัญ
จากนั้นเปิดหน้าตัวอย่างให้ฉันดู พร้อมบอกวิธีเปิดครั้งถัดไป
```

Agent ควรเลือกเทคโนโลยีจากความต้องการและสภาพแวดล้อมของคุณ หากต้องติดตั้ง runtime หรือ package ให้ทำในช่วงนี้ตามที่งานต้องใช้ ไม่มีคำสั่งติดตั้งตายตัวสำหรับ Dashboard ทุกแบบ

เริ่มด้วยข้อมูลที่มีสิทธิ์ใช้ หากข้อมูลจริงยังไม่พร้อม ใช้ข้อมูลจำลองเพื่อดูหน้าตาและฟังก์ชันก่อน โดยแสดงสถานะให้ชัด การมีหน้าจอที่เปิดได้ไม่ได้แปลว่าเชื่อมข้อมูลสดสำเร็จแล้ว

**สิ่งที่ควรได้:** รุ่นแรกที่เปิดได้จริง พร้อมวิธีเปิด แหล่งข้อมูลที่ใช้ และสิ่งที่ผ่านการตรวจหรือยังไม่ได้ตรวจ

## 5. ลองใช้ แล้วคุยให้ตรงใจ

ลองทำงานที่ตั้งใจจะทำจริงหนึ่งรอบ แล้วบอก Agent ว่าติดตรงไหน การชี้จุดจากหน้าจอช่วยให้แก้ได้ชัดกว่า “ทำให้สวยขึ้น” อย่างเดียว:

| สิ่งที่รู้สึกตอนลอง | ตัวอย่างคำสั่งต่อ |
|---|---|
| ข้อมูลแน่นเกินไป | “เก็บหน้าหลักไว้ 3 ตัวเลขสำคัญ ย้ายรายละเอียดไปกดดูต่อ แล้วเปิดให้ดูใหม่” |
| หาสิ่งที่อยากรู้ไม่เจอ | “ให้เรียงหุ้นตามผลตอบแทนช่วงที่เลือก และคงช่วงเวลานั้นเมื่อเปลี่ยนหุ้น” |
| ไม่แน่ใจตัวเลข | “แสดงสูตร ช่วงวันที่ และแหล่งข้อมูลของตัวเลขนี้ แล้วตรวจเทียบกับตัวอย่างหนึ่งรายการ” |
| กราฟดูยาก | “ใช้สีที่แยกกันชัด เพิ่มชื่อเส้น และลองดูด้วยจอมือถือ” |
| อยากอัปเดตข้อมูล | “เสนอวิธีอัปเดตจากแหล่งที่ฉันมี ทดสอบหนึ่งรอบ แล้วแสดงเวลาข้อมูลล่าสุด” |

ให้ Agent แก้ทีละชุดที่ตรวจผลได้ แล้วเปิดดูซ้ำ อัปเดต brief เมื่อคุณเปลี่ยนใจเรื่องสำคัญ เพื่อให้รอบถัดไปยึดความต้องการล่าสุด

หากเปลี่ยนขอบเขตมาก ให้เรียก `to-spec` อีกครั้งตามต้องการ Skills ที่ต้องให้ผู้ใช้เรียกจะไม่ถูกเรียกต่อกันเองเพียงเพราะอยู่ในลำดับนี้

**สิ่งที่ควรได้:** Dashboard ที่คุณลองใช้แล้วบอกได้ว่าช่วยตอบโจทย์ และรายการสิ่งที่อยากพัฒนาต่อซึ่งแยกจากงานที่เสร็จแล้ว

## ก่อนจบคลาส

ลองทำสิ่งเหล่านี้ด้วยตัวเอง โดยให้ Agent ช่วยอธิบายเมื่อจำเป็น:

- เปิด Dashboard อีกครั้งจากวิธีที่บันทึกไว้
- ทำงานหลักหนึ่งอย่าง เช่น ดูความกระจุกตัวของพอร์ตหรือเทียบหุ้นในช่วงเวลาเดียวกัน
- เลือกตัวเลขหนึ่งตัวแล้วตามกลับไปถึงสูตร วันที่ และแหล่งข้อมูล
- ลองกรณีไม่มีข้อมูลหรือข้อมูลไม่ครบ เพื่อดูว่าหน้าจออธิบายได้ชัดเจนหรือไม่
- บอกได้ว่าอะไรใช้ข้อมูลจริง อะไรยังเป็นตัวอย่าง และจะปรับอะไรต่อ

## วิธีเรียก Skills

บางแอปใช้คำสั่ง `/grill-with-docs`, `/to-spec` และ `/implement` ได้ บางแอปต้องบอกชื่อหรือพาธไฟล์ เช่น:

```text
อ่าน .agents/skills/implement/SKILL.md แล้วใช้สกิลนี้ทำงานตามสเปกที่เราตกลง
```

โฟลเดอร์ `.agents/skills/` เป็นสำเนาในโปรเจกต์ การดาวน์โหลด repo ไม่ได้ติดตั้ง Skills ส่วนกลาง และแชตเว็บไซต์ทั่วไปไม่ได้อ่านโฟลเดอร์ในเครื่องให้อัตโนมัติ ดู[คู่มือ Skills](skills.md) หากแอปไม่พบสกิล

กลับไปที่ [START.md](../START.md) เพื่อเริ่มคุย หรือดู[ภาพรวม Flow](workflow.md) เพื่อเลือกว่าจะทำขั้นไหนต่อ
