# คู่มือคลาส: จาก Prompt ถึง Dashboard ที่ตรวจผลได้

เป้าหมายของคลาสคือให้ผู้เรียนเปิดโปรเจกต์ อธิบายว่าตัวเลขมาจากไหน ปรับโจทย์หนึ่งอย่าง และอัปเดตข้อมูลได้ โดยใช้ Skills เป็นวิธีทำงานซ้ำ ไม่ต้องดัดแปลง Skills ทุกตัวให้รู้จักหุ้นไทย

## ก่อนเริ่ม

เตรียม Node.js 22+, สำเนา repo ของตัวเอง และแอป Agent ถ้าต้องการให้ AI ช่วยเขียนโค้ด เริ่มด้วยข้อมูลจำลองที่แจกมากับโปรเจกต์ได้ทันที ข้อมูล Efin จริงใช้ในช่วงนำเข้าเมื่อคุณมีไฟล์และสิทธิ์ใช้งานแล้ว

```bash
npm run doctor
npm start
```

เปิด `http://localhost:3100` และชี้ให้เห็นป้ายข้อมูลจำลอง อย่าเปลี่ยนชื่อ DEMO เป็นชื่อหุ้นจริงโดยยังใช้ตัวเลขจำลอง

## ช่วงที่ 1 — อ่านผลให้เป็น

เลือก `DEMO_BANK` เทียบ `DEMO_SET` แล้วตอบให้ได้ว่า:

1. ข้อมูลครอบคลุมวันที่ใด และวันที่ล่าสุดคือวันใด?
2. ช่วงคำนวณนับจากข้อมูลกี่ช่วง?
3. หุ้นให้ผลตอบแทนเท่าไร benchmark เท่าไร และต่างกันกี่ percentage points?
4. กราฟที่เริ่ม 100 แสดงการเปลี่ยนแปลงเทียบ benchmark อย่างไร?

ใช้[ตัวอย่างคำนวณใน Data contract](data-contract.md#ตรวจด้วยตัวอย่างเล็ก) คำนวณด้วยเครื่องคิดเลขก่อนเชื่อผลบนหน้าเว็บ

**ผลส่งมอบ:** คำอธิบายตัวเลขหนึ่งตัวพร้อมวันที่เริ่มและสิ้นสุด

## ช่วงที่ 2 — ให้ Agent เข้าใจงานจากจุดเดียว

ทำสำเนา [dashboard-brief.md](../templates/dashboard-brief.md) เป็นเอกสารงานของตัวเอง เติมกลุ่มผู้ใช้ คำถามที่ต้องตอบ benchmark แหล่งข้อมูล และสิ่งที่จะตรวจรับ แล้วสั่ง Agent:

```text
อ่าน AGENTS.md และ brief ที่ฉันกรอก
สรุปสิ่งที่จะเปลี่ยนและวิธีตรวจผลแบบสั้น
ตรวจ Skills ที่มีอยู่จริงก่อนเลือกใช้ โดยเคารพกติกาการเรียกของแต่ละตัว
ทำการเปลี่ยนแปลงหนึ่งอย่างให้เปิดใช้ได้ แล้วรายงานสิ่งที่ทดสอบจริง
```

เลือกการเปลี่ยนแปลงเล็ก เช่น ชื่อหน้า ช่วงผลตอบแทน หรือการจัดลำดับตาราง เก็บความต้องการของคลาสไว้ใน brief/config และกติกาโปรเจกต์ ไม่ใส่ข้อความหุ้นไทยซ้ำลงทุก Skill

**ผลส่งมอบ:** การเปลี่ยนแปลงหนึ่งอย่างที่เห็นได้ พร้อมผลตรวจ

## ช่วงที่ 3 — นำ CSV ของตัวเองเข้า

เก็บไฟล์ต้นฉบับไว้ แล้วทำไฟล์สำหรับนำเข้าที่มีคอลัมน์ `date,symbol,close` ตาม [Data contract](data-contract.md) ถ้าไฟล์ Efin ใช้ชื่อหัวตารางต่างกัน ให้ทำ mapping จากหัวตารางจริง โดยระบุว่าราคาเป็น adjusted หรือ unadjusted อย่าเดาความหมายจากชื่อที่ไม่ชัด

ปรับ `symbols`, `benchmark` และ `lookbackPeriods` ใน `dashboard.config.json` ให้ตรงกับ CSV ก่อน แล้วกด **โหลด snapshot ใหม่** เพื่อให้หน้าเว็บอ่าน config ล่าสุด จากนั้นเลือกไฟล์เพื่อดูตัวอย่าง (ช่วงที่ config เปลี่ยนแต่ยังไม่ได้เลือก CSV อาจแสดงว่าไม่มีข้อมูลที่คำนวณได้) เมื่อพร้อมใช้เป็นข้อมูลหลักให้รัน:

```bash
npm run import -- "/path/to/input.csv"
```

เปิดหรือรีเฟรชหน้า Dashboard ตรวจว่าชื่อหุ้น benchmark วันล่าสุด และจำนวนช่วงตรงกับไฟล์ มีวันที่ร่วมกันพอสำหรับ lookback ที่เลือกหรือไม่ ถ้าไม่พอให้แก้แหล่งข้อมูลหรือช่วงคำนวณ ห้ามเติมราคาเอง

**ผลส่งมอบ:** ข้อมูลหนึ่งชุดที่อธิบายที่มาและตรวจค่าปลายทางได้

## ช่วงที่ 4 — ใช้ Skills ให้ตรงงาน

เลือกจาก Skills ที่ติดตั้งจริง ดู[คู่มือความเข้ากันได้](upstream-skills.md):

| สิ่งที่กำลังทำ | วิธีทำงานที่เหมาะ |
|---|---|
| อธิบายโจทย์และเลือกขอบเขต | เติม brief; ผู้เรียนเรียก skill สัมภาษณ์เองถ้าต้องการ |
| ลองหน้าตาก่อนสร้างจริง | prototype |
| คำนวณหรือรับข้อมูล | ทดสอบพฤติกรรมผ่าน parser/calculation interface |
| ตัวเลขผิดหรือหน้าไม่ขึ้น | diagnosing-bugs |
| ตรวจการเปลี่ยนก่อนส่ง | code-review โดยระบุจุดเปรียบเทียบและ brief |

ชื่อเหล่านี้เป็นแนวทางเลือก ไม่ใช่การรับรองว่ามี Skill ดังกล่าวอยู่ในทุกแอป และไม่ใช่คำสั่งให้ Agent เรียก Skills แบบ user-invoked เอง

**ผลส่งมอบ:** บอกได้ว่าใช้ Skill ใด เพื่ออะไร และมันสร้างผลลัพธ์อะไรที่ตรวจได้

## ช่วงที่ 5 — อัปเดตซ้ำและเตรียมตั้งเวลา

นำ CSV รอบใหม่ที่ผ่านการตรวจมารัน:

```bash
npm run refresh -- "/path/to/input.csv"
```

รันซ้ำด้วยไฟล์เดิม ตรวจว่าไม่เพิ่มแถวซ้ำ และวันข้อมูลไม่ได้ถูกเปลี่ยนให้ดูใหม่ขึ้นเพียงเพราะสั่ง refresh วันนี้ จากนั้นเติม [refresh-report.md](../templates/refresh-report.md)

วางแผนว่าใครหรือระบบใดจะสร้าง CSV ใหม่ งานจะรันบนเครื่องใด เมื่อใด และจะทราบได้อย่างไรว่าล้มเหลว ตาม[คู่มือ Scheduling](scheduling.md) ตัว starter ยังไม่เปิด scheduler และไม่ได้ดึง Efin โดยอัตโนมัติ

**ผลส่งมอบ:** การอัปเดตที่ทดสอบด้วยมือแล้วหนึ่งรอบ และแผนตั้งเวลาที่ระบุแหล่งข้อมูลชัด

## จบคลาส

รัน `npm test`, `npm run check`, `npm run doctor` และทำ[รายการตรวจรับ](acceptance-checklist.md) ให้ครบ บอกแยกกันว่าอะไรเปิดใช้ได้แล้ว อะไรทดสอบแล้ว และอะไรยังเป็นแผน
