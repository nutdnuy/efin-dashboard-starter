# เตรียมงานอัปเดตข้อมูลและตั้งเวลา

งานที่ต้องทำซ้ำคือ **ได้ไฟล์ใหม่ → ตรวจข้อมูล → บันทึกชุดที่ผ่าน → ตรวจวันที่ล่าสุด → รายงานผล** ต้องทำเส้นทางนี้ด้วยมือให้สำเร็จก่อนนำไปตั้งเวลา

Starter มีคำสั่ง refresh ที่รันซ้ำได้ แต่ **ยังไม่มี scheduler ที่เปิดใช้งาน และยังไม่มี Efin API adapter** การเปิดหน้า Dashboard ไม่ได้ทำให้มีงานเบื้องหลังคอยดาวน์โหลดราคา

## 1. ระบุว่าใครสร้างข้อมูลรอบใหม่

เลือกเส้นทางที่มีจริงในสภาพแวดล้อมของคุณ:

| เส้นทาง | สิ่งที่ต้องมี |
|---|---|
| Export CSV เอง | ไฟล์ที่ export ได้จริง และ mapping คอลัมน์ตาม Data contract |
| เครื่องมือ Efin/MCP ที่เชื่อมไว้ | รายชื่อ tools ที่เปิดให้ใช้จริง สิทธิ์บัญชี และผลลัพธ์ที่ตรวจได้ |
| API ที่มีเอกสารและสิทธิ์ใช้งาน | เอกสาร endpoint/auth/limits และ adapter ที่พัฒนาและทดสอบเพิ่ม |

ให้ Agent ตรวจเครื่องมือที่เข้าถึงได้ก่อนเสมอ การเห็นชื่อ Efin หรือ MCP ไม่ได้แปลว่ามีสิทธิ์ดึงทุกข้อมูล อย่าสร้าง endpoint, token หรือผลลัพธ์ตัวอย่างแล้วรายงานว่าเชื่อมต่อจริง

เก็บ credentials ในกลไกที่แอปหรือผู้ให้บริการกำหนด ไม่ใส่ใน CSV, prompt, config ที่ commit หรือไฟล์ public

## 2. ทดลองคำสั่งจริง

จาก root ของ repo:

```bash
npm run refresh -- "/absolute/path/to/latest-export.csv"
```

คำสั่งอ่านไฟล์นั้น ตรวจตาม [Data contract](data-contract.md) และบันทึกใน `data/private/current.json` ถ้าผ่าน การชี้ path เดิมโดยไม่ได้เปลี่ยนเนื้อหาไฟล์จะได้ข้อมูลเดิม ไม่ใช่ข้อมูลตลาดรอบใหม่

ตรวจวันที่ของราคา หุ้น benchmark และผลตอบแทนบน Dashboard แล้วรันซ้ำด้วยไฟล์เดิมเพื่อยืนยันว่าไม่เพิ่มข้อมูลซ้ำ บันทึกผลด้วย [Refresh report](../templates/refresh-report.md)

ลองไฟล์ที่ผิดรูปแบบหนึ่งครั้งเพื่อยืนยันว่าแจ้งข้อผิดพลาดและไม่แทนที่ข้อมูลดีชุดก่อนหน้า อย่าแก้ไฟล์ต้นฉบับที่ใช้งานจริงเพื่อสร้างกรณีทดสอบ

## 3. ออกแบบตารางงาน

กำหนดให้ครบก่อนสร้างงาน:

- **งาน:** วิธีสร้าง CSV ใหม่และคำสั่ง refresh ที่ทดสอบแล้ว
- **เครื่องที่รัน:** ต้องเข้าถึง repo, Node.js, ไฟล์ และ credentials ที่จำเป็นได้
- **เวลา:** ระบุวัน เวลา และเขตเวลา `Asia/Bangkok` เช่น 18:00 เป็นเพียงตัวอย่างให้ปรับตามเวลาที่แหล่งข้อมูลพร้อม
- **วันหยุด:** วันจันทร์–ศุกร์ไม่เท่ากับวันซื้อขาย SET เสมอไป ต้องมีนโยบายเมื่อไม่มีข้อมูลรอบใหม่
- **ผลสำเร็จ:** ข้อมูลผ่าน validation และวันล่าสุดตรงตามที่คาด ไม่ใช่เพียงคำสั่งถูกเรียก
- **เมื่อล้มเหลว:** เก็บชุดข้อมูลเดิม รายงานเหตุผล และไม่สรุปว่าราคาอัปเดตแล้ว
- **วิธีหยุด:** รู้ว่าจะ pause/delete งานที่สร้างไว้จากตรงไหน

การตั้งเวลาในแอป Agent และ scheduler ของระบบปฏิบัติการเป็นคนละทาง เลือกจากความสามารถจริงของแอปและเครื่องที่ใช้ หากแอปรันบน cloud อาจอ่านไฟล์ local path ของคุณไม่ได้

## 4. ตัวอย่าง Prompt สำหรับสร้างงานเมื่อพร้อม

ข้อความนี้เป็นแม่แบบ **ยังไม่ได้สร้างงานจริง** เติมค่าที่ระบุและให้ Agent ตรวจความพร้อมก่อน:

```text
ช่วยเตรียมงานอัปเดต Dashboard ของ repo [absolute repo path]
เวลา [วันและเวลา] เขตเวลา Asia/Bangkok

แหล่งข้อมูล: [วิธีสร้าง CSV ใหม่ที่ทดสอบแล้ว หรือเครื่องมือที่เข้าถึงได้จริง]
ไฟล์นำเข้า: [absolute CSV path]
ขั้นตอนบันทึก: npm run refresh -- "[absolute CSV path]"

ตรวจว่าเครื่องที่จะรันเข้าถึง Node.js, repo, ไฟล์ และสิทธิ์ข้อมูลได้
อ่าน Data contract และตรวจวันที่ล่าสุดของหุ้นเทียบ benchmark
ถ้าไม่มีข้อมูลใหม่หรือ validation ไม่ผ่าน ให้เก็บชุดเดิมและแจ้งสาเหตุ
รายงานวันที่ข้อมูลล่าสุด จำนวนหุ้น และผลตรวจ ห้ามสร้างราคาขึ้นเอง

แสดงรายละเอียดงานและวิธีหยุดงานก่อนเปิดใช้
หลังสร้างแล้วระบุรหัสงาน เวลารันถัดไป และผลทดสอบหนึ่งรอบ
```

ถ้าโจทย์เป็นเพียงการเรียนรู้ scheduling ให้หยุดที่แผนและการทดสอบ refresh ด้วยมือ การเขียนเอกสารตัวอย่างไม่จำเป็นต้องเปิดงานประจำบนบัญชีของผู้เรียน

## ขอบเขตของหลักฐาน

แยกสถานะให้ชัด: **เตรียม prompt**, **ทดสอบคำสั่ง**, **สร้างงาน**, **งานรันแล้ว**, **ข้อมูลอัปเดตสำเร็จ** แต่ละข้อใช้หลักฐานต่างกัน การผ่านขั้นแรกไม่ยืนยันขั้นถัดไป
