# Resolve only what the next useful version needs

Use the conversation, brief and any existing spec before asking new questions.
Separate facts the agent can inspect from choices only the learner can make.
Use find-information for source facts, ask-questions for choices, define-terms
for ambiguous vocabulary, and preview-dashboard to make a visual choice tangible.

For a clear request, write the compact spec and continue the authorized build.
Do not insert phase approvals for the spec, test seams or task list when the
current request already settles them.

For a large uncertain effort, record .scratch/<effort>/map.md with the desired
outcome, accepted decisions, unresolved choices, exclusions and the next action.
Create a decision record under decisions/ only when it has a concrete question.
Use status open, in-progress, resolved or out-of-scope. Record the answer and
its evidence, then update the map with a pointer rather than duplicating it.
Record an owner and any blocking decisions. Work only unblocked questions;
claim one before starting and release the claim if work stops. A human choice
stays unresolved until the human answers. The coordinator owns shared statuses.

Resolve independent factual questions while waiting for a human choice if tools
permit. Never answer the human's question on their behalf. Do not create tasks
for vague unknowns prematurely or expand beyond the stated outcome.

When enough is known for the next useful version, continue building if that
was requested. There is no one-decision-per-session limit. If the request was
planning only, deliver the plan and open decisions without modifying the app.
